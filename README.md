# 📈 암호화폐 퀀트 자동 매매 시스템 (업비트 & 빗썸)

이 프로젝트는 지정 거래소 API를 활용하여 메인 전략(업비트) 및 서브 전략(빗썸) 포트폴리오를 자동으로 매매하고, 거래 결과를 디스코드 웹훅으로 매일 전송하는 퀀트 자동 매매 시스템입니다. GitHub Actions를 사용하여 무상태(Stateless) 환경에서 매일 자동으로 가동되도록 설계되었습니다.

---

## 📂 파일 구성 및 기능

```
quant-bitcoin/
├── .github/workflows/main.yml    # GitHub Actions 워크플로우 (매일 09:05 KST 실행)
├── requirements.txt              # 파이썬 의존성 패키지 목록
├── config.py                     # 전역 상수, API 키 및 환경 설정 로드
├── discord_bot.py                # 디스코드 리포트 메시지 포맷팅 및 전송 봇
├── bithumb_api.py                # 빗썸 v1 REST API 연동 클라이언트 클래스
├── test_monday.py                # 빗썸 월요일 상승장 종목 선정 로직 독립 테스트 스크립트
└── main.py                       # 메인 오케스트레이터, 보조지표 계산 및 매매 실행 로직
```

## ⚙️ 상세 전략 알고리즘

### 1. 메인 전략 (업비트)
* **대상 자산**: BTC, ETH (목표 비중 각 50%)
* **실행 주기**: 매일 오전 09:05 KST
* **개별 추세 필터**:
  * **BTC (상하한 ±2% 버퍼 적용)**:
    * 신규 매수 (미보유 시): `현재가 >= 200일 SMA * 1.02`
    * 매도/현금화 (보유 시): `현재가 < 200일 SMA * 0.98`
  * **ETH (14일 ATR의 1.5배 버퍼 적용)**:
    * 신규 매수 (미보유 시): `현재가 >= 150일 SMA + (ATR(14) * 1.5)`
    * 매도/현금화 (보유 시): `현재가 < 150일 SMA - (ATR(14) * 1.5)`
* **비중 밴드 리밸런싱**:
  * BTC와 ETH 모두 추세 필터를 통과하여 보유 중일 때만 평가합니다.
  * 한쪽 자산의 비중이 목표 비중(50%) 대비 10%p를 초과하여 벗어날 때(40% 미만 혹은 60% 초과)만 50:50 비중으로 재조정 매매를 수행합니다.

### 2. 서브 전략 (빗썸)
* **대상 자산**: 빗썸 원화(KRW) 마켓의 알트코인 (BTC, ETH 제외)
* **공통 시장 필터 (업비트 BTC 기준)**:
  * 상승장 판정: `현재가 >= 200일 SMA * 1.02`
  * 하락장 판정: `현재가 < 200일 SMA * 0.98`
  * 버퍼 구간(Standby): 가격이 버퍼 범위 내에 있을 경우, 과거 일봉 데이터를 역순으로 탐색하여 최근에 확실히 결정된 시장 상태를 현재 상태로 계승(유지)합니다.
* **매일 점검 (09:05 KST)**:
  * 공통 시장 필터가 **하락장**일 경우, 요일에 상관없이 보유한 모든 알트코인을 즉시 전량 시장가 매도하여 안전하게 현금화(KRW)합니다.
* **주간 리밸런싱 (매주 월요일 09:05 KST)**:
  * 공통 시장 필터가 **상승장**일 때만 실행합니다.
  * 종목 선정 단계:
    1. 최근 7일 평균 거래대금 상위 10개 종목 추출
    2. 선별된 10개 종목 중 최근 14일 수익률(상대 모멘텀) 상위 4개 종목 최종 선정
  * 매매 실행: 선정된 4개 종목에 빗썸 서브 자산의 각 25%씩 동일 비중(1/N)으로 매수합니다. (기존 종목 중 탈락한 종목은 전량 매도 후 교체)

## 🚀 사용 및 실행 방법

### 1. 로컬 개발 환경 구성

아래 명령어를 통해 필요한 라이브러리를 설치합니다:
```bash
python -m pip install -r requirements.txt
```

### 2. API 키 및 환경 변수 구성
프로그램 실행을 위해 아래의 환경 변수(GitHub Secrets) 설정이 필요합니다.
* `UPBIT_ACCESS_KEY` & `UPBIT_SECRET_KEY`: 업비트 자산조회 및 주문 권한 API 키
* `BITHUMB_ACCESS_KEY` & `BITHUMB_SECRET_KEY`: 빗썸 자산조회 및 주문 권한 API 키
* `DISCORD_WEBHOOK_URL`: 거래 잔고 보고서를 받을 디스코드 채널의 웹훅 주소

### 3. 모의 실행 (Dry-Run 테스트)
실제 매매 주문을 보내지 않고 연산 결과와 디스코드 알림 포맷만 확인하고 싶다면, `DRY_RUN` 환경 변수를 `True`로 주어 실행합니다:
```powershell
# Windows PowerShell 예시
$env:UPBIT_ACCESS_KEY="자신의키"
$env:UPBIT_SECRET_KEY="자신의키"
$env:BITHUMB_ACCESS_KEY="자신의키"
$env:BITHUMB_SECRET_KEY="자신의키"
$env:DISCORD_WEBHOOK_URL="디스코드웹훅주소"
$env:DRY_RUN="True"
python main.py
```

### 4. 빗썸 로테이션 알고리즘 단독 테스트
요일이나 시장 필터 조건에 구애받지 않고 빗썸에서 현재 시각 기준 거래대금 및 모멘텀 분석을 수행해 유망 알트코인 4개를 선별하는 연산을 직접 테스트해볼 수 있습니다.
```bash
python test_monday.py
```

### 5. GitHub Actions 프로덕션 운영 설정
1. 깃허브 리포지토리를 생성하고 코드를 푸시합니다.
2. 리포지토리의 `Settings` -> `Secrets and variables` -> `Actions` 메뉴로 이동합니다.
3. `Repository secrets` 항목에 아래 변수들을 정확히 추가합니다:
   - `UPBIT_ACCESS_KEY`
   - `UPBIT_SECRET_KEY`
   - `BITHUMB_ACCESS_KEY`
   - `BITHUMB_SECRET_KEY`
   - `DISCORD_WEBHOOK_URL`
4. 설정이 완료되면 매일 오전 09:05 KST (00:05 UTC)에 자동으로 GitHub Actions 워크플로우가 기동되며 매매 결과가 지정한 디스코드 채널로 전송됩니다.
5. 필요한 경우 GitHub Actions 탭에서 `Run workflow` 버튼을 클릭하여 즉시 수동으로 매매를 기동할 수도 있습니다.
